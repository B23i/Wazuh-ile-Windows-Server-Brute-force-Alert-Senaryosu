# Wazuh SIEM Lab: Detecting Windows RDP Brute-Force Attacks

This project demonstrates the deployment of a defensive Security Information and Event Management (SIEM) environment using **Wazuh** to detect and analyze brute-force attacks against a Windows Server Remote Desktop Protocol (RDP) service.

The objective of this lab is to collect Windows security events, correlate failed authentication attempts, and generate custom alerts that identify potential brute-force activity.

# Project Overview

This lab was created to demonstrate how a SIEM platform can collect, correlate, and analyze security events generated by a Windows Server system.

A controlled brute-force simulation was performed against an RDP service, and Wazuh was configured to:

* Collect Windows Security Event Logs
* Detect failed login attempts
* Correlate repeated failures
* Generate brute-force alerts
* Provide visibility through the Wazuh Dashboard

> All activities were performed within an isolated VirtualBox laboratory environment. No third-party systems or public infrastructure were targeted.

---

# Objectives

The primary objectives of this project were:

* Deploy a functional Wazuh SIEM environment
* Monitor Windows Security Events
* Detect Event ID 4625 (Failed Logon Events)
* Create custom Wazuh detection rules
* Simulate an RDP brute-force attack
* Validate alert generation and event correlation

# Wazuh Server Installation

Wazuh was installed on an Ubuntu Server virtual machine using the official installation script.

```bash
curl -sO https://packages.wazuh.com/4.12/wazuh-install.sh
sudo bash ./wazuh-install.sh -a
```

The installation deployed:

* Wazuh Manager
* Wazuh Indexer
* Wazuh Dashboard

on a single server.

# Connecting Windows Server to Wazuh

To monitor Windows security events, the Wazuh Agent was installed on the Windows Server system.

The deployment process included:

1. Navigating to **Deploy New Agent** in the Wazuh Dashboard.
2. Entering the Wazuh Server IP address.
3. Downloading and installing the generated agent package.
4. Starting the **WazuhSvc** service.

After installation, the agent successfully appeared as **Active** within the dashboard.

![Figure 6 - Active Windows Agent](images/sekil_6.jpg)

This confirmed that Windows Event Logs were being forwarded to the Wazuh Manager.

# Custom Brute-Force Detection Rules

Windows records failed authentication attempts using **Event ID 4625**.

To identify brute-force activity, two custom Wazuh rules were created.

## Rule 100100

Detects individual failed logon events.

## Rule 100101

Detects multiple failed logon attempts occurring within a short period and classifies them as a potential brute-force attack.

Generated alert:

```text
LAB - Possible Windows RDP brute-force attack detected
```

MITRE ATT&CK Mapping:

```text
T1110 - Brute Force
```

![Figure 7 - Custom Detection Rules](images/sekil_7.jpg)

After modifying `local_rules.xml`, the Wazuh Manager service was restarted to load the new rules.

# Attack Simulation

A test user account named:

```text
badguy
```

was created on the Windows Server system.

The account password was intentionally excluded from the password list to ensure that all authentication attempts would fail.

Hydra was used on Kali Linux to perform controlled RDP password guessing attempts.

```bash
hydra -l badguy -P passwords.txt -t 1 -W 3 rdp://192.168.56.4
```

The objective was not to gain access but to generate failed authentication events.

![Figure 8 - Hydra Brute-Force Simulation](images/sekil_8.jpg)
